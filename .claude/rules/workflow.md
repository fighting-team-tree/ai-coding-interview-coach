# Workflow Rules (Claude Code)

## 실질적 작업 4단계

멀티파일 편집 · 디렉토리 구조 변경 · 제안서 수정 · 아키텍처 변경 · 커밋 준비가 해당됨.

1. **탐색** — 현재 상태 파악, 관련 파일 읽기
2. **브리핑** — 변경 파일 · 예상 결과 · 트레이드오프를 텍스트로 제시
3. **승인** — 텍스트 기반 선택지 또는 번호형 옵션으로 명시적 동의 확인
4. **실행** — 합의한 범위만 기계적으로 수행

계획과 실행은 반드시 **별도 턴**으로 분리.
사용자가 "진행해줘"라고 해도 3단계(명시적 승인 확인)는 생략 불가.

## 모두의 창업 문서 작업 기본값

- 현재 저장소의 기본 작업은 **코드 구현보다 신청서와 기획 문서 개선**이다.
- 문서 변경 브리핑에는 반드시 **변경 대상 문단, 기대 메시지 변화, 심사위원 관점의 효과**를 포함한다.
- 문서 수정은 표현 다듬기보다 **설득 구조 개선 단위**로 다룬다.
- 기존 제품 개발 자산은 삭제보다 **근거 자료로 재배치**하는 쪽을 우선 검토한다.
- 승인 필수 범위는 **주요 방향 전환, 구조 변경, 큰 폭의 기획 문서 수정**을 기본값으로 한다.

## 승인 불필요 (즉시 실행)

- 파일 읽기 / 코드 검색
- `git status`, `git diff`, `git log` 등 읽기 전용 명령
- 탐색적 확인
